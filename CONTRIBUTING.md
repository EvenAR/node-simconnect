# Contributing

Thanks for helping improve `node-simconnect`. This project is a TypeScript
CommonJS library that talks directly to SimConnect, so small binary layout changes
can have large effects. Keep changes focused and verify them locally.

## Setup

```sh
npm ci
```

Use Node.js 18 or newer and npm 8 or newer.

## Local Checks

Run the complete agent/contributor check before opening a pull request:

```sh
npm run agent:check
```

The individual commands are:

```sh
npm run typecheck
npm run lint
npm run format:check
npm test
npm run build
```

Use `npm test -- <pattern>` for targeted Jest runs while iterating.

## Documentation and Samples

- Generate API reference docs with `npm run generate-api-reference`.
- Samples live in `samples`. They should demonstrate real usage and stay as small
  as practical.
- Many samples require a running simulator and working SimConnect configuration.
  Unit tests should remain simulator-free and suitable for CI.

## Adding or Changing SimConnect Support

When adding protocol or API coverage:

- Add or update enums, flags, DTOs, and TypeScript types as needed.
- Build outgoing messages through `SimConnectPacketBuilder` and `RawBuffer`.
- Parse incoming messages through the appropriate `src/recv` class.
- Preserve little-endian reads/writes, fixed-width string sizes, and field order.
- Export public additions through `src/index.ts`.
- Add a focused packet/parser test when possible, or a sample when simulator
  behavior is the only practical verification path.

Do not edit `dist` directly. It is generated by `npm run build`.
