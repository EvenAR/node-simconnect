# Agent Guide

This repository is a TypeScript CommonJS client for the SimConnect protocol used by
Microsoft Flight Simulator, FSX, and Prepar3D. Most changes touch binary protocol
encoding/decoding, public TypeScript exports, samples, or simulator-free tests.

## Start Here

- Install dependencies with `npm ci`.
- Run the full local check with `npm run agent:check`.
- For focused work, run targeted Jest tests with `npm test -- <pattern>`.
- Do not edit `dist` directly. It is generated by `npm run build`.

## Project Map

- `src/SimConnectConnection.ts` contains the main public handle and most SimConnect
  API methods.
- `src/SimConnectSocket.ts` owns socket framing and dispatch from raw messages.
- `src/SimConnectPacketBuilder.ts` builds outgoing packet headers and bodies.
- `src/RawBuffer.ts` wraps little-endian binary reads and writes.
- `src/recv` contains parsed incoming SimConnect message classes.
- `src/dto` contains reusable data structures and buffer helpers.
- `samples` contains runnable usage examples. Some require a simulator.
- `tests` contains simulator-free Jest tests and packet fixtures.

## Protocol Invariants

- SimConnect packet data is little-endian.
- Outgoing packet headers are 16 bytes:
    - bytes 0-3: packet size
    - bytes 4-7: protocol version
    - bytes 8-11: packet type or function id
    - bytes 12-15: packet id
- Fixed-width strings must preserve their expected byte length and null padding.
- Reads and writes are offset-sensitive. Keep field order aligned with the
  official SimConnect wire format and the matching parser or builder.
- Public library exports should flow through `src/index.ts`.

## Change Guidance

- Prefer adding or updating simulator-free tests when changing packet encoding,
  parsing, buffer helpers, enums, or public API methods.
- Keep samples practical and minimal. They may demonstrate simulator behavior, but
  CI should not depend on a running simulator.
- When adding SimConnect API coverage, update the relevant enum or type, add the
  packet builder or recv parser path, export public pieces from `src/index.ts`
  when needed, and add either a focused test or a sample.
- Keep generated API docs out of normal feature changes unless the task is
  specifically about documentation publishing.
